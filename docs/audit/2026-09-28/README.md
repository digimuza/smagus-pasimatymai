# Conversation flow visual check

Captured from the final Docker image at 390 × 844 and 1440 × 900 on 2026-09-28. Cookies were accepted and the included question library was seeded.

1. **Landing — healthy.** The promise and free-play action are visible in the first phone viewport. The layered sample card previews the real game. [Mobile](01-landing.png) · [Desktop](06-landing-desktop.png)
2. **Mode choice — healthy.** Couples is visually primary and free; the other modes are clearly marked Pro. All four cards fit the phone width without horizontal scrolling. [Screenshot](02-audience.png)
3. **First question — healthy.** The light card gives the question clear priority. Skip, Super, and Answered are visible buttons, so swiping is optional. [Screenshot](03-game.png)
4. **Premium prompt — healthy.** Plans and included features are readable. A guest sees “Sign in to continue”; the previous action closed this panel without guidance. The panel now has a close control. [Screenshot](04-paywall.png)
5. **Sign-in — healthy.** The guest action opens the sign-in panel. Its inputs have accessible names and it has a visible close control. [Screenshot](05-sign-in.png)

The screens were checked in English; the landing was also checked in Lithuanian. The browser suite covers both languages and the core play flow. Screenshots alone cannot establish screen-reader announcements, keyboard focus order, contrast ratios, or behavior under 200% zoom. A dedicated assistive-technology pass is still needed before claiming accessibility compliance.
